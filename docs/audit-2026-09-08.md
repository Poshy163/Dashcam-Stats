## Read-only inspection and its limits

Inspection used bounded GETs for health, system info/database statistics, settings, queue,
recordings, ingest history, telemetry quality, and filtered logs. List samples used 1–30 rows;
the quality endpoint has a source-enforced issue limit. No database backup endpoint, raw media
export, playback stream, OSD re-decode, retention action, or device-control endpoint was invoked
on production. The live browser reached the sign-in screen; authenticated inspection used API
headers rather than putting a master credential in browser history.

**Unexpected existing GET side effect:** the one dashboard `/api/status` call can run
`evaluate_safety`, whose writability check creates and removes a temporary dotfile on a
writable footage mount. The code path was discovered later in the audit; whether that
particular call reached/succeeded at the probe was not independently recorded. Thus this
audit cannot claim literally zero production filesystem writes. Further production status
calls were stopped. The local fix removes that probe from status GETs, returns unknown
writability, and explains that cleanup performs its own checks. Retention's actual deletion
safety checks remain unchanged. Ordinary server access logging also occurs naturally.

No original raw recordings or sidecars were available through a verified, non-mutating raw
download route: `/stream/{id}` calls `ensure_playable`, which can write a remux cache. It was
deliberately not used. One already-generated 46,847-byte rear-camera thumbnail was inspected;
it shows a burned-in time/coordinate/speed overlay. It cannot establish original embedded
streams, OCR accuracy, plate accuracy, or capture finalisation. The private thumbnail stays
outside the repository and is not part of this report. Local media validation uses generated
fixtures and an isolated migrated database, not a copied production database.

## Pipeline map

| Stage | Owner and durable output | Completion/failure contract |
| --- | --- | --- |
| Capture/finalisation | Vendor recorder, outside this repository; time/channel filenames and MPEG-TS | Stable complete-file exposure is inferred from transfer guards, not proven on device. |
| Discovery and ignition gate | `ingest/poller.py`, `ingest/adb.py`, `ingest/puller.py`; run history and radio lease | Unknown/on ignition holds; mature files are selected; duplicate flat names across directories are rejected. |
| Transfer | ADB control plus bounded raw TCP/tar chunks; `.ingest_staging` | Incomplete final members are not published; reconnect retries files, not unsupported byte-range resumes. |
| Verify/publish/reclaim | `ingest/puller.py::commit`, `adb.py::delete_if_unchanged` | Expected size, file sync, atomic rename, POSIX directory sync; current source size/mtime checked again before reclaim. Collisions receive byte comparison. |
| Index | `scanner/discovery.py`, recording rows and sampled fingerprint provenance | Settling is separate from discovered; new post-read stat rejects a fingerprint from a changing file. |
| Metadata/thumbnail | `pipeline/stages.py::stage_inspect`, `hardware/ffmpeg.py`; media columns and thumbnail | Probe failure is differentiated from infrastructure failure; no empty successful probe. Thumbnail-first scheduling is retained. |

## Metadata and compatibility

Newly exposed fields are `container`, `video_profile`, `fps_container`, `bitrate` (bits/s),
`pix_fmt`, `audio_codec`, `audio_sample_rate` (Hz), and `audio_channels`. They already existed
in SQLite and are populated by the production probe, so there is **no migration or extra
decode**. Implausible declared frame rates remain null; the recovered usable frame rate is
separate. The UI labels file-probe properties, filename/overlay capture-time origin and
configured timezone. Raw `probe_json` and private internal markers remain excluded.

No rotation, embedded GPS, altitude, IMU measurements or unsupported camera identity was
invented. Deterministic heading/distance, OCR estimates, interpolated/paired fixes, and manual
decisions remain distinct. Candidate additions requiring original/device evidence include
data streams/sidecars, rotation/time base, stable recording generation/session identity,
recorder event markers and recorder-versus-device clock offset.

API fields are additive except `storage.footage_writable`, which now permits null; external
status clients must treat it as unknown. The updated bundled UI does. Older API responses
without the new media properties remain supported by optional frontend fields. Android fresh
installs now need explicit webhook credentials; already-saved credentials are retained.
HTTP webhook URLs outside private/loopback IPv4 must move to HTTPS. Redirects are refused.

Card behaviour changes intentionally: pre-existing same-size local names will no longer be
deleted from the card merely on size evidence. **Acquisition of recorder-reused same-size
names remains unresolved**: the flat-name delta still skips them, so a stable generation/
digest receipt and collision-versioning design is needed. The safer deletion policy may
retain more footage on the card. Conflicts preserved in staging require operator review;
there is no automatic conflict retention/deletion policy in this change.

## Measurement and validation

The same untouched checkout baseline passed 1,706 backend tests with 13 skips in 91.57 s.
The final integrated results are recorded in [the handoff](audit-handoff-2026-09-08.md).
Fixtures use separate directories/databases and mocked device transports; the visual check
ran the real metadata stage and FastAPI/React stack with lifespan disabled, no workers or
scheduler, and synthetic footage only.

Measured local durability cost: eight 1 MiB files, three repetitions, median 2.339 ms for
plain renames versus 62.165 ms for durable commit (about 7.5 ms/file). This is a correctness
trade-off on this Windows disk, not a prediction of NFS/card transfer speed. Remote stat
rechecks remain one control call per directory; collision comparison is bounded to 1 MiB
chunks and runs only when an equal-size destination exists at finalisation. No higher
concurrency, compression, model thresholds, sampling rate or detection model was introduced.

The log-dedupe regression retains 3/3 distinct stage events versus 1/3 on the previous key,
while an identical repeat is still suppressed. Additional stored log rows are bounded by
the existing queue/key limits and log retention. No production runtime speedup is claimed.

The classifier itself was not changed or accuracy-benchmarked. One production thumbnail and
synthetic regression cases are insufficient to report real-world precision/recall. Metadata
projection needs no reanalysis and returns the same stored values through list/detail/export.

## Remaining findings and next-phase evidence

1. Rotate/revoke the exposed credential after coordinating all consumers; removing it from
   source does not remove it from history or installed APKs. Use a separate scoped webhook
   credential in a future protocol revision instead of distributing the full-access key.
2. Radio-watchdog lease failures caused recent aborted backups. Inspect existing device
   watchdog files/logs and timing only after authorisation; never bypass the guard to improve
   a throughput number.
3. GPU inference remains disabled. A separate controlled driver/runtime assessment is needed;
   the audit did not clear its failure marker or reproduce GPU allocation failure.
4. Stage revisions are static and do not fingerprint historical settings. Model/threshold
   changes affect later jobs without marking all old results stale. The OSD template cache
   also needs explicit profile/parser provenance before a targeted invalidation design.
5. Successful partial decodes and missing plate-frame fallbacks still lack a persisted,
   explicit coverage interval in the main recording response. Viewer wording is corrected;
   a complete sampled-coverage model is not implemented.
6. Variable-frame-rate/keyframe fallback seeks and front/rear alignment need representative
   originals. Current synthetic tests cannot establish every vendor timestamp behaviour.
7. Python dependency ranges and the companion builder image leave reproducibility gaps.
   Backend strict typing has substantial pre-existing debt; see final check results.
8. Linux container/device execution remains unverified here. A build is not an installation,
   and mocked shell tests do not prove vendor shell support or crash durability on NFS.

The exact head-unit questions, packages, files, commands and design-changing evidence are
in the companion review's read-only investigation plan. **That plan has not been executed.**
